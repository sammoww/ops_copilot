Q1: What is LCEL and why do production teams use it?
LCEL (LangChain Expression Language) is a declarative syntax for composing modular cognitive chains using Python's bitwise OR operator (|). It standardizes every component into the Runnable interface, giving streaming, async parity, batching, and LangSmith tracing out of the box with zero boilerplate.
Q2: How does the pipe | operator work under the hood in Python?
In Python, A | B invokes the magic method A.__or__(B). In LangChain, the Runnable base class overrides __or__ to return a RunnableSequence, wiring the output of component A directly as input to component B.
class Runnable:
    def __or__(self, other):
        return RunnableSequence(first=self, middle=[], last=other)
Q3: Why separate format_docs from retrieval?
Separation of concerns. The vector store's job is purely semantic retrieval (returning structured List[Document] objects with metadata). Downstream tasks (FastAPI schemas, citation buttons, Ragas evaluations) need raw metadata. If the vector store returned a raw string, all structured metadata would be lost!
